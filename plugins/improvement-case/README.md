# improvement-case

이력서·경력기술서에 넣을 **"문제 / 개선 사례"** 를 작성하고 검산하는 Claude Code plugin.

증명 대상은 하나다:

> **"고쳤다"가 아니라 "어떻게 알아냈고, 왜 다시 안 생기게 만들었나"**

```
증상이 운영에서만 드러났다
  → 계측/근거로 원인을 특정했다
    → 개별 수정 + 재발을 막는 구조를 함께 넣었다
      → 수치와 구조적 효과를 둘 다 남겼다
```

이 골격에서 벗어나는 글은 **작업 기록**이지 개선 사례가 아니다. 이 플러그인은 골격을 강제하고,
빈 칸을 지어내는 대신 `✍️` 마커로 남겨 되묻는다.

## 설치

marketplace 등록 후:
```
/plugin install improvement-case@padosol
```

## 사용

```
이번에 고친 커넥션 풀 이슈, 이력서 사례로 정리해줘
```

```
내 개선 사례 3번 좀 봐줘 — 뭐가 비었는지
```

```
트러블슈팅 경험 하나 추가하려는데 기존 사례랑 겹치나?
```

**쓴다:** 개선 사례를 새로 쓸 때, 기존 사례를 보강·검산할 때, 방금 해결한 이슈를 경력 자산으로
남길 때.
**안 쓴다:** 자기소개서·지원 동기, 이력서 전체 구조 첨삭, PR/커밋 설명 작성.

## 제목 공식

```
N. [증상 — 과거형 서술 한 문장] — [조치], [결과 수치]
```

> `2. 업로드가 몰리면 일반 API 응답까지 밀렸다 — 전용 스레드 풀로 격리, 동시 실행 2건 제한`

결과 수치가 없으면 **무엇을 막았는지**를 대신 쓴다 —
"운영에서만 터지던 조인 실패를 CI에서 차단".

## 5블록 최소 요건

| 블록 | 반드시 들어가는 것 | 빠지면 |
|---|---|---|
| 문제 | 증상 / 발견 시점 / 개별 수정으로 안 되는 이유 / 제약 조건 | 재발 방지 구조가 과잉 대응으로 보인다 |
| 원인 | 확인 수단 / 메커니즘 / 기존 안전망이 못 잡은 이유 | 운으로 찾은 건지 구분이 안 된다 |
| 해결 | 조치+근거 한 문장 / 개별 수정+재발 방지 / 실패 경로 / 부수 조치 | 운영 경험이 없어 보인다 |
| 측정 | 수치 / 구조적 효과 / 운영성 / **측정 환경** | "그 3초는 어떤 조건이죠?" 에 무너진다 |
| 비고 | 버린 대안 / 치른 대가 / 남은 한계 | 트레이드오프를 모르는 사람으로 보인다 |

해결에 등장하는 **모든 숫자는 문제·원인에서 근거를 갖는다.**

## 문체

| 위치 | 문체 |
|---|---|
| 제목 · 문제 · 원인 | 과거형 서술 — "~드러났다", "~밀렸다" |
| 해결 · 측정 | 명사형 압축 — "~차단", "~확보" |

앞은 이야기, 뒤는 이력서. 숫자는 반올림하지 않는다(102개, 854건, 4건).
