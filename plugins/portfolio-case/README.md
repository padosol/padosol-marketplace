# portfolio-case

포트폴리오 사례를 **5블록(문제 · 원인 · 해결 · 측정 · 비고)** 구조로 작성하는 Claude Code plugin.

지키려는 것은 하나다:

> **소제목만 세로로 훑어도 사례 전체가 추적된다**

```
문제 1  간헐적 로그인 끊김        문제 2  응답 지연 및 요청 실패
원인 1  인스턴스 로컬 세션 저장    원인 2  리다이렉트당 단건 조회
해결 1  세션 저장소 외부화        해결 2  로컬 캐시 적용
측정 1  세션 유실 문의 건수       측정 2  평균 응답 시간, 조회 호출 수
```

같은 번호는 같은 대상을 가리킨다. 대응이 어긋나는 자리가 곧 논리 구멍이다.
그래서 이 플러그인은 본문을 바로 쓰지 않고 **대응표를 먼저 세워 구멍을 잡은 뒤** 본문을 쓴다.

## 설치

marketplace 등록 후:
```
/plugin install portfolio-case@padosol
```

## 사용

```
이 항목들 포트폴리오로 정리해줘
```

```
로그인 풀리는 이슈 고친 거, 5블록으로 써줘
```

```
포트폴리오 사례 2번 좀 봐줘 — 뭐가 비었는지
```

**쓴다:** 포트폴리오 사례를 새로 쓸 때, 기존 사례를 5블록으로 재구성할 때,
러프한 항목 나열을 읽히는 문서로 만들 때, 사례의 논리 구멍을 찾을 때.

**안 쓴다:** 자기소개서 · 지원 동기, 이력서 전체 첨삭, PR/커밋 설명 작성.

## 무엇을 강제하는가

### 1. 소제목 + 번호 대응

블록은 **소제목(명사구 4~12자) + 내용(1~3줄)** 으로 쓴다.
블록마다 관점이 바뀐다 — 문제는 **증상**, 원인은 **구조**, 해결은 **조치**.

### 2. 블록별 주어와 시제

| 블록 | 주어 | 시제 | 대표형 |
|---|---|---|---|
| 문제 | 사용자 / 시스템 | 현재형 | "~하는 현상 발생" |
| 원인 | 코드 / 설정 / 쿼리 | 과거형 단정 | "~였습니다" |
| 해결 | 나 | 과거형 능동 | "~를 적용했습니다" |
| 측정 | 지표 | 수치 대비 | "~ → ~" |
| 비고 | 나 / 남은 과제 | 미래·조건형 | "~는 필요합니다" |

주어가 섞이면 "성능이 개선되도록 캐시를 적용해서 응답이 빨라졌습니다" 같은 문장이 나온다.

### 3. 수치는 원인과 측정에만

문제 블록에 "3초 걸림"을 쓰면 측정 블록이 할 말을 잃는다.

- 문제: 조회가 느리다는 문의가 접수됨
- 측정: 평균 응답 3초 → 0.3초

### 4. 원인은 단정형, 미확인은 비고로

`~로 추정됩니다` · `~로 보입니다` 는 쓰지 않는다.
원인을 확실히 파악했기 때문에 해결할 수 있었던 것이므로, 추측성 표현이 남으면
규명이 덜 된 채 조치했다는 인상을 준다.

확인하지 못한 영역은 원인에서 흐리지 말고 **비고의 "미확인 구간"으로 분리**한다.
그러면 "원인을 모른다"가 아니라 "어디까지 규명했고 어디부터가 다음 과제인지 안다"로 읽힌다.

### 5. 해결에는 버린 대안을 한 줄

기술 나열은 누구나 한다. 선택의 이유는 겪어본 사람만 쓴다.

> 로드밸런서 스티키 세션도 검토했으나 인스턴스 증설 시 부하가 쏠려 저장소 분리를 선택했습니다.

### 6. 지어내지 않는다

수치 · 측정 도구 · 측정 조건 · 확인 수단을 추측으로 채우지 않는다.
사용자가 말하지 않은 값은 `✍️` 마커로 남기고 되묻는다.
마커가 하나라도 남아 있으면 그 사례는 미완성이며, 완성했다고 보고하지 않는다.

## 검산 6문항

1. 블록마다 소제목이 붙어 있고, 소제목만 읽어도 흐름이 잡히는가
2. **문제 1번 — 원인 1번 — 해결 1번 — 측정 1번이 같은 대상을 가리키는가**
3. 문제 블록에 원인이 섞여 있지 않은가
4. 원인에 무엇을 보고 알았는지가 있고, 추측성 표현 없이 단정형인가
5. 해결에 선택하지 않은 대안이 한 줄이라도 있는가
6. 측정에 도구와 조건이 있는가

2번이 조치와 결과의 불일치를 잡는 장치다. 소제목만 세로로 훑으면 대부분 걸러진다.

## improvement-case 와의 차이

두 플러그인 모두 5블록을 쓰지만 **최적화 대상이 다르다.**

| | `portfolio-case` | `improvement-case` |
|---|---|---|
| 산출물 | 포트폴리오 문서 | 이력서 · 경력기술서 사례 한 건 |
| 구조 장치 | 소제목 + 블록 간 번호 대응표 | 제목 공식(증상 — 조치, 수치) |
| 문제 블록 시제 | 현재형 "~현상 발생" | 과거형 서술 "~드러났다" |
| 수치 배치 | 원인 · 측정에만 | 제한 없음 |
| 문체 | 개조식 + 서술형 배합 | 앞은 서술, 뒤는 명사형 압축 |
| 검산 | 6문항 | 13항목 |

**읽히는 구조**를 잡을 때는 이 플러그인, **한 줄로 압축**할 때는 `improvement-case` 를 쓴다.
